# CLI end-to-end gate

From the `go/` module directory, run `go test -count=1 -v ./e2e` or `go test -race ./e2e`. CI runs this package
in a separate blocking step as well as through `go test ./...`.

The harness builds `memory` once per package run. It imports only the Go standard
library and executes the real binary for all identity, policy, space and memory
operations. It does not invoke application Go APIs, reuse application test
helpers, read local identity private files, or emulate legitimate admission.

The owner and two agents each have a separate process environment, `--home`,
Ed25519 identity generated by the CLI, ephemeral SSH commit signer, and clones.
Git uses explicit fixture configuration, synthetic authors, file-only transport,
disabled host configuration/agents, and no network. Hooks are disabled except
for the bounded fixture-owned pre-push barrier in the concurrency test. Git signing defaults
to false in the fixture: commands must explicitly request `-S`. Every introduced
commit is checked for a good signature against fixture-owned public signers.
Remotes, homes and keys live under `t.TempDir()`; the once-built binary uses
`os.MkdirTemp`. Set `TMPDIR` to an owned directory **outside any Git repository**
if the normal system temporary directory is unsuitable. Go caches follow the
test caller's environment. Go, Git and `ssh-keygen` must already be available.
Child environments allow only toolchain/cache/temp variables, use an offline
local Go toolchain and disable ambient Go configuration; credentials and unrelated
host environment settings are not forwarded.

| Tool | Entry points used by the gate | Artifacts |
| --- | --- | --- |
| Go | `go build -buildvcs=false -o BINARY ../cmd/memory`; `go test -count=1 -v ./e2e`; `go test -race ./e2e` | Once-built temporary binary; test verdicts on stdout |
| Git | `git init --bare --initial-branch=main`, `git commit -S`, `git push`, `git log --format=%G?`, `git update-ref` | Disposable repositories and signed commits under test temp roots |
| OpenSSH | `ssh-keygen -q -t ed25519 -N '' -f KEY` | Separate ephemeral commit keys and public allowed-signers fixture |

The JSON helper checks one closed envelope, exact exit codes, typed refusals,
stderr expectations and data classification. Relevant payload objects are also
checked for extra/missing/duplicate fields. Checker controls retain known-invalid
output examples next to a valid control. Read comparisons pin logical UTC time.

## Phase A

| Scenario | Test | Required result |
| --- | --- | --- |
| 1 | `TestPhaseAOwnerAndTwoAgents` | Owner initializes project, registers/grants both agents, both clone the pin and pass sync/check with separate keys/homes/clones |
| 2 | `TestPhaseAForgedPushExcluded` | Raw Git push carries bad-signature and unregistered-key records; both checks exit 5 with exact diagnostics, both recalls exclude them and retain exactly one legitimate CLI-written assertion |
| 3 | `TestPhaseAHistoryRewrite` | Owner rewinds fixture remote to genesis; both sync/read exit 4, preserve exactly one assertion with its identity/content/issuer and the complete last verified data/cursors, and recover after restore |
| 4 | `TestPhaseAReaderRevocation` | B loses recall/changes (exit 3, no data), A retains the exact assertion; signed regrant restores B's populated reads |
| 5 | `TestPhaseATwoReadableSpaces` | Each agent recalls distinct assertions from both spaces in ID order with independent cursors, stable JSON and a composite changes cursor |

The raw-Git exception constructs adversarial records only; record bodies have
intentionally invalid signatures. A known registered key reaches
`invalid_signature`, while an unregistered identity reaches `unregistered_key`.
The exact codes ensure malformed fixture/setup errors cannot satisfy the test.
All raw Git commits themselves remain signed. Rewrites use compare-and-swap
`update-ref` on the disposable bare remote; no force push is used.

Scenario 1 checks the newly initialized empty space. Scenarios 2–5 pair their
negative or aggregation assertions with nonempty CLI-written controls: rejected
neighbors must not hide a legitimate record, rollback must retain both readers'
last verified record and cursor, revocation must leave the other reader's record
visible, and combined recall must contain each space's distinct record. Scenario 3
checks exact cardinality/content and byte-identical read data before, during and
after the rewind; retaining only an old cursor with empty views cannot pass.
Phase B adds revision, concurrency and source semantics to complete the gate.

## Phase B

| Scenario | Test | Required result |
| --- | --- | --- |
| 6 | `TestPhaseBDecisionRevisionAndChanges` | A adds a documentary decision with a session source; B syncs and recalls/explains its exact content, issuer and source ref |
| 7 | `TestPhaseBConcurrentRevision` | Two independent keys/homes for one issuer build replacement candidates from the same parent; exactly one publishes, the loser gets `version_conflict`, retries from a fresh read token, and both readers converge byte-for-byte |
| 8 | `TestPhaseBDecisionRevisionAndChanges` | Distinct issuer B cannot replace A; missing/stale caller preconditions publish nothing; A's token-bound replacement is uniquely current for B |
| 9 | `TestPhaseBAssessAndPromote` | Writer grant controls targeted assessment; source reader and target writer grants independently control promotion; the derivative has the promoting issuer and a local source citation |
| 10 | `TestPhaseBDecisionRevisionAndChanges` | A cursor captured at scenario 6 yields exactly replacement version 2 and the later assertion; a current cursor yields zero changed refs; malformed cursors refuse |
| 11 | `TestPhaseBSessionSource` | B sees the exact runtime/session/message, raw-text digest, multiline Unicode excerpt and unavailable state in recall/explain; revoke hides all data, A continues reading, regrant restores B |

The source presentation contract is recorded in
[session source presentation](#session-source-presentation).

A decision in scenario 6 is a documentary assertion about a decision. The trusted
CLI profile does not supply external authority receipts, so this test does not
claim an authoritative `decision_record` or confirmation of its truth.

The replace race uses independently registered keys for the **same issuer**:
issuer-only replacement cannot legitimately race two different issuers. The homes,
identity key material, Git signers, environments and clones remain independent.
Scenario 8 uses distinct issuers to test the complementary refusal. The pre-push
hook records both actual candidate parents before releasing either normal push,
has a bounded wait, and does not change admission or push behavior. The gate checks
one remote commit after the race and one after the retry, clean HEAD/index/tree,
good signatures and exact reader output. Unpublished losing commits may remain in
reflog, as the adapter contract permits.

Refusals compare remote/local heads, committed tree, index, working-tree status
and reachable/reflog commit count after prior sync. A typed error alone is not
sufficient. Assessment admission does not execute a check or manufacture an
evidence witness. Promotion replay must preserve its exact receipt and commit.
Changes compares authorized projections, not raw Git writes: the replaced old
version and auxiliary intake/revision/source records are not extra current change
refs. Unchanged views may still contain items, with `no_change` and empty refs.

### Session source presentation

Package 0.3.0 K-SRC-1 supplies the view's citation-closed `sources` table. Scenario
11 checks the exact locator components, raw retained-text digest, multiline
Unicode excerpt including its trailing newline, and `availability: unavailable`
in both recall and explain. It verifies the signed atomic assertion/source/basis
batch. Revoking B's space reader grant yields `not_authorized`, null data and no
source ref; A keeps reading. Regrant restores the complete source payload.

```sh
go -C go test -count=1 -run '^TestPhaseBSessionSource$' -v ./e2e
```

The write uses `--source-session runtime:planning:message:42` and `--source-text -`.
The digest covers the retained excerpt, not necessarily the entire message.
The CLI has no per-record disclosure input: this e2e control proves space access
revocation. Kernel S46–S49 independently cover hidden source/citation changes and
audience redaction. No live resolver, source truth or independent authority is
claimed.

## Stage 5: two owners

Run the complete stage-5 gate with:

```sh
go -C go test -count=1 -timeout=30m -run '^TestStage5TwoOwners$' -v ./e2e
```

`stage5_test.go` uses four separate local bare remotes: `o1/platform`,
`o2/platform`, `o1/project:alpha` and `o2/project:beta`. The owners
`o1/owner` and `o2/owner` and agents `o1/agent:a1` and `o2/agent:b1`
have separate homes, process environments and identity/commit keys. The harness
simulates out-of-band public-key and signed-advertisement exchange. Each owner
attests foreign key registrations in the target policy and signs publications
in its own directory. Each agent manually pins only its own platform; both own
and foreign project pins come from that directory.

| Scenario/control | Subtest or fixture step | Required result |
| --- | --- | --- |
| Owner setup and discovery | Fixture setup | Four spaces, distinct keys, platform-only manual pins, two owner-wrapped project advertisements in each directory |
| Documentary decision and assumption | Fixture setup | A1 writes a decision with a session source and multiline Unicode excerpt; B1 writes an assumption in its own project |
| Listed but never granted | `listed-but-ungranted` | Both registered foreign agents can discover a project but get `not_authorized`, null data and unchanged configuration when reading it; each own reader retains the populated record |
| Reciprocal sharing | `reciprocal-source-reads` | Owner-signed foreign reader grants permit both reads; recall and explain retain the original issuer, exact locator, raw-text digest, complete excerpt and `unavailable` source state |
| Revoke/regrant while listed | `revoke-and-regrant` | B1 loses all Alpha data while A1 keeps reading; regrant restores B1's record and source payload |
| Foreign writer and direct write | `cross-owner-writes-and-promotion` | Writer grant gives `cross_owner_writer`; direct write gives `not_authorized`; config, remote/local heads, tree, index, status and reachable/reflog commit count stay fixed |
| Cross-owner promotion | `cross-owner-writes-and-promotion` | `cross_owner_promotion`, unchanged target/config and both populated project controls retained |
| Tampered advertisement | `tampered-advertisement-and-third-identity` | Wrong genesis gives `directory_mismatch`, unchanged config and no retained clone/cache/staging; restoring the valid advertisement permits discovery |
| Ungranted third identity | `tampered-advertisement-and-third-identity` | `o2/agent:c1` can use its granted own directory but cannot read the listed project; B1 still reads it |
| Other owner's directory | `other-owner-directory-without-pin` | The unknown platform refuses with `unknown_space` and no config change; the own pinned directory remains usable |
| Directory non-authority | `directory-is-not-a-kernel-write` | Republish in both directories leaves all four populated semantic views unchanged and does not move either project head |
| Manual access without an entry | `manual-pin-without-entry` | Neither directory lists O1's platform; a separate B1 home with its target grant and manual platform pin reads its marker. That foreign platform pin cannot serve as B1's own discovery root |
| Lost-home recovery | `both-home-recoveries` | Both memory homes are wiped, new identity keys differ from the lost keys, owners register the replacements, and platform-only manual pins recover each own project's original record/source |
| Agent writer publishes | `writer-signed-directory-entry` | CLI publication refuses without side effects; a raw valid writer-signed entry receives `directory_unauthorized`, is absent from discovery, and leaves a valid project neighbour usable |

The decision is a documentary assertion, not an authority-receipted
`decision_record`. The manual-access control uses a nonempty platform marker so
it needs no fifth remote and neither directory has any entry for that target.
Its extra home intentionally exercises the manual-pin exception, independently
of the two agents' platform-only discovery/recovery paths. Source assertions pin
logical UTC time and include the excerpt's trailing newline.

View invariance compares all CLI-projected semantic fields after checking item
and source shapes/attribution. It removes only Git cursor attribution and
cursor-bound write tokens, because a platform publication legitimately advances
its Git head. Both project Git heads must remain unchanged. The raw directory
exception uses an independently encoded, correctly signed adversarial object
with an ephemeral in-memory key registered to the agent writer; it imports no
application API and reads no identity private file. Its Git commit remains signed.

The listed-but-ungranted row is the reader-authority instrument witness. In an
isolated source copy, substituting a target owner's read principal for an
ungranted directory reader must fail this row with
`listed-but-ungranted: target reader check bypassed`; the restored implementation
must pass. The plant is never part of the committed gate. The task outcome records
the plant, restored run and exact tested source.

**Hosting ACL gap:** file remotes have no git hosting authentication or repository
ACL. This gate proves CLI, signed-policy, discovery, source and recovery behavior;
it does not prove that a hosting service prevents cloning or pushing. A deployed
sharing setup must separately grant and revoke repository access. Withdrawing a
directory entry is not a substitute for revoking the target reader grant or
hosting access.
